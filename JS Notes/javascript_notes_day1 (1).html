Topic 01
⚙️ V8 Engine
Google's JS engine that powers Chrome and Node.js

DEFINITION

V8 is Google's open-source, high-performance JavaScript and WebAssembly engine written in C++. It compiles JS directly to native machine code instead of interpreting it line by line.

One line: V8 is the engine that reads your JavaScript and makes the computer execute it — fast.

PIPELINE

Your JS Code
   ↓
Parser       → code → AST (Abstract Syntax Tree)
   ↓
Ignition     → interpreter — runs bytecode fast at startup
   ↓
TurboFan     → JIT compiler — compiles "hot" code to machine code
   ↓
Native Machine Code  → runs directly on CPU ⚡

WHERE V8 IS USED

PlatformRole
Google ChromeBrowser JS execution
Node.jsServer-side JS runtime
DenoModern JS/TS runtime
ElectronDesktop app framework
Topic 02
🟢 Node.js
JavaScript runtime that runs JS outside the browser

DEFINITION

Node.js is an open-source, cross-platform JavaScript runtime environment that lets you run JS on servers, desktops, or any machine — not just inside a browser.

Node.js = V8 Engine + libuv + Node APIs
 ├── V8 Engine   → Executes JavaScript
 ├── libuv       → Handles async I/O (files, network)
 └── Node APIs   → fs, http, path, crypto...

KEY TRAITS

Asynchronous Non-Blocking Single-Threaded Event Loop NPM (2M+ packages)

SIMPLE HTTP SERVER

const http = require('http');
const server = http.createServer((req, res) => {
  res.writeHead(200);
  res.end('Hello World!');
});
server.listen(3000); // → http://localhost:3000
Key insight: Before Node.js, JS only ran in browsers. Node brought JS to the server — now one language works for both frontend AND backend.
Topic 03
📦 var / let / const
Three ways to declare variables — each with different rules

COMPARISON TABLE

Featurevarletconst
ScopeFunctionBlockBlock
Reassignable✅ Yes✅ Yes❌ No
Redeclarable✅ Yes❌ No❌ No
Hoisted✅ as undefined✅ TDZ error✅ TDZ error
Modern use❌ Avoid✅ Use✅ Prefer

var — FUNCTION SCOPED (AVOID IN MODERN JS)

var x = 10;
var x = 20;   // ✅ redeclare ok — dangerous!

if (true) { var y = 5; }
console.log(y); // ✅ 5 — leaks out of if block! Bug!

// Hoisting — var moves to top as undefined
console.log(a); // undefined (no error)
var a = 5;

let — BLOCK SCOPED (USE WHEN REASSIGNING)

let count = 0;
count = 1;      // ✅ reassign ok
let count = 2;  // ❌ SyntaxError — cannot redeclare

if (true) { let z = 5; }
console.log(z); // ❌ ReferenceError — stays in block ✅

// TDZ — accessing before declaration throws error
console.log(b); // ❌ ReferenceError (Temporal Dead Zone)
let b = 5;

const — BLOCK SCOPED (YOUR DEFAULT CHOICE)

const PI = 3.14;
PI = 3.15;         // ❌ TypeError — cannot reassign

// ⚠️ const prevents reassignment, NOT mutation!
const user = { name: 'Ravi' };
user.name = 'Kumar';   // ✅ mutation allowed
user = {};              // ❌ reassignment NOT allowed

const nums = [1, 2, 3];
nums.push(4);           // ✅ push is mutation — allowed
nums = [5, 6];          // ❌ reassignment — not allowed
Best Practice: Always use const by default. Switch to let only when you need to reassign. Never use var in modern JS.
Topic 04
🌍 var vs let — Real Life Examples
3 everyday analogies to make scope crystal clear

🏫 EXAMPLE 1 — CLASSROOM WHITEBOARD

var = One Shared Whiteboard
Teacher writes a number on the board and sends 3 students to the library.

"Come back when the bell rings and tell me what's on the whiteboard."

• Sends Student 1 → board: 0
• Sends Student 2 → board: 1
• Sends Student 3 → board: 2
• Loop ends → board erased → now says 3

Bell rings. All 3 look at the same whiteboard.
Student 1 → "3" ❌
Student 2 → "3" ❌
Student 3 → "3" ❌
let = Personal Sticky Note
Same classroom — but teacher gives each student their own sticky note with their number.

• Student 1 gets note → 0
• Student 2 gets note → 1
• Student 3 gets note → 2

Nobody can change anyone else's sticky note.

Bell rings. Each looks at their own note.
Student 1 → "0" ✅
Student 2 → "1" ✅
Student 3 → "2" ✅

🏏 EXAMPLE 2 — CRICKET SCOREBOARD

var = One Big Scoreboard
3 journalists are asked to note the score each over and report at the end of the match.

• Over 1 → scoreboard: 10
• Over 2 → scoreboard: 45
• Over 3 → scoreboard: 89 (final)

Match ends. All 3 journalists check the same scoreboard.
All 3 report → 89, 89, 89 ❌
(original scores lost!)
let = Each Journalist's Notepad
Each journalist writes in their own notepad at their over.

• Journalist 1 notes → 10
• Journalist 2 notes → 45
• Journalist 3 notes → 89

Match ends. Each reads from their own notepad.
Reports → 10, 45, 89 ✅
(each captured their moment!)

📱 EXAMPLE 3 — WHATSAPP GROUP vs SCREENSHOT

var = WhatsApp Group Chat
3 friends each join a group chat at different times. They are asked: "What was the last message when you joined?"

But someone kept editing the last message. By the time all 3 answer, it was edited to "Bye!"

All check the same group chat.
All 3 say → "Bye!" ❌
(their original message gone!)
let = Screenshot at Join Time
Each friend took a screenshot the moment they joined the group.

• Friend 1 screenshot → "Hi"
• Friend 2 screenshot → "How are you?"
• Friend 3 screenshot → "Let's meet!"

Screenshot is frozen — no one can change it.
Friend 1 → "Hi" ✅
Friend 2 → "How are you?" ✅
Friend 3 → "Let's meet!" ✅
Golden Rule: var = everyone shares one copy, sees the latest value. let = everyone gets their own private frozen copy at that moment.
Topic 05
⏱️ setTimeout — Deep Dive
Non-blocking delay — schedules code, doesn't pause code

DEFINITION

setTimeout(fn, ms) schedules a function to run after a delay. It is non-blocking — JS does NOT wait for it. It moves to the next line immediately.

Restaurant analogy: You order food (setTimeout). Waiter says "ready in 100ms". You don't stare at the wall — you talk, drink water (next lines run). When food is ready, waiter brings it (callback fires).

STEP BY STEP — WITH let ✅

for (let i = 0; i < 3; i++) {
  setTimeout(() => console.log(i), 100);
}
console.log("Loop done!");
STEP 1 — i = 0
→ let creates own copy of i=0 for this iteration
→ setTimeout scheduled for 100ms — does NOT wait
→ moves to next iteration immediately
STEP 2 — i = 1
→ let creates own copy of i=1 for this iteration
→ setTimeout scheduled for 100ms — does NOT wait
→ moves to next iteration immediately
STEP 3 — i = 2
→ let creates own copy of i=2 for this iteration
→ setTimeout scheduled for 100ms — does NOT wait
→ i++ → i=3 → (3 < 3) is false → loop ends
STEP 4 — synchronous code runs
→ console.log("Loop done!") runs IMMEDIATELY ✅
→ Call Stack is now empty
STEP 5 — after 100ms
→ All 3 callbacks fire from queue
→ Each has its own copy of i → prints 0, 1, 2 ✅

STEP BY STEP — WITH var ❌

for (var i = 0; i < 3; i++) {
  setTimeout(() => console.log(i), 100);
}
console.log("Loop done!");
STEP 1 — i = 0
→ ONE shared var i created in memory (hoisted)
→ setTimeout scheduled — callback stores reference to i (not value 0!)
→ i becomes 1
STEP 2 — i = 1
→ same shared i is now 1
→ setTimeout scheduled — callback still points to same i
→ i becomes 2
STEP 3 — i = 2
→ same shared i is now 2
→ setTimeout scheduled — callback points to same i
→ i++ → i=3 → loop ends. i is now 3 in memory.
STEP 4 — synchronous code runs
→ console.log("Loop done!") runs IMMEDIATELY ✅
→ i is still 3 sitting in memory
STEP 5 — after 100ms
→ All 3 callbacks fire
→ All check same shared i → i = 3 → prints 3, 3, 3 ❌

MEMORY PICTURE

// With let — 3 separate private boxes
Iteration 1 → [ i = 0 ]  ← callback 1 reads this
Iteration 2 → [ i = 1 ]  ← callback 2 reads this
Iteration 3 → [ i = 2 ]  ← callback 3 reads this

// With var — ONE shared box that keeps changing
        [ i ]  ← only ONE box exists
          ↓
     0 → 1 → 2 → 3  (keeps updating)

All 3 callbacks look here ──→ all see 3 ❌
Topic 06
🔄 Event Loop
How JavaScript handles async on a single thread

DEFINITION

The Event Loop is JavaScript's mechanism to handle asynchronous code on a single thread. It constantly checks: "Is the Call Stack empty? If yes — pick the next callback from the queue and run it."

3 KEY AREAS

1. Call Stack      → runs your synchronous code right now
2. Web APIs        → handles setTimeout, fetch, click events
3. Callback Queue  → holds callbacks waiting for their turn

// Rule: If Call Stack is EMPTY → pick from Queue → run it

EXECUTION TIMELINE

// 0ms — synchronous loop runs instantly
i=0 → setTimeout → Web APIs ────────────────────┐
i=1 → setTimeout → Web APIs ─────────────────┐  │
i=2 → setTimeout → Web APIs ──────────────┐  │  │
"Loop done!" → Call Stack → prints ✅     │  │  │
Call Stack now EMPTY                       │  │  │
                                           │  │  │
// 100ms — callbacks move to queue, then stack
prints 0  ◄──────────────────────────────────┘  │  │
prints 1  ◄─────────────────────────────────────┘  │
prints 2  ◄────────────────────────────────────────┘
Why "Loop done!" prints first: setTimeout goes to Web APIs — not the Call Stack. Synchronous code runs on Call Stack immediately. Callbacks only enter the stack after it's completely empty.
Topic 07
⚡ Interpreted vs Compiled
JavaScript is a hybrid — JIT compiled at runtime

DEFINITION

JavaScript is traditionally called interpreted but modern JS engines use JIT (Just-In-Time) compilation — a hybrid approach. Starts as interpreted (fast startup), then compiles frequently-run "hot" code to native machine code (fast execution).

COMPARISON

InterpretedCompiledJIT — Modern JS
When compiledNeverBefore runningDuring running
Startup speedFastSlowFast ✅
Run speedSlowFastFast ✅
ExamplesOld JS, PythonC, C++, RustModern JS, Java JVM

HISTORY

// 1995–2008: Pure interpreted 🐢
Code → Interpreter → line by line → output

// 2008–now: JIT with V8 ⚡
Code → Parser → Ignition (bytecode) → TurboFan (machine code) → output
Interview answer: "JavaScript is traditionally interpreted, but modern engines like V8 use JIT — it starts fast like an interpreter, then compiles hot code to native machine code for speed."
Topic 08
🎯 Interview Q&A
Top 10 questions from today — read these before your interview!
Q: What is the V8 engine?
Google's open-source JS engine in C++. Powers Chrome and Node.js. Uses JIT compilation — Ignition (interpreter) + TurboFan (compiler) for fast execution.
Q: What is Node.js?
A JS runtime built on V8 that runs JavaScript outside the browser. Uses non-blocking event loop. Made of V8 + libuv + Node APIs.
Q: Difference between var, let, const?
var = function-scoped, hoisted as undefined, avoid. let = block-scoped, reassignable. const = block-scoped, not reassignable. Use const by default, let when needed.
Q: Why does var in loop with setTimeout print wrong?
var is function-scoped — all iterations share one i. By the time setTimeout fires (100ms later), the loop already made i = 3. let gives each iteration its own private copy.
Q: What is the Event Loop?
JS mechanism to handle async on a single thread. Checks if Call Stack is empty, then picks callbacks from the queue. Enables non-blocking execution.
Q: Is JavaScript interpreted or compiled?
Hybrid — uses JIT compilation. Starts interpreted for fast startup, then V8's TurboFan compiles hot (frequently run) code to native machine code for speed.
Q: What is a closure?
A function that remembers variables from its outer scope even after that scope ends. The setTimeout arrow function "closes over" i from the loop — that's a closure.
Q: What is the Temporal Dead Zone?
The gap between when let/const is hoisted and when it's initialized. Accessing it during this gap throws ReferenceError. var avoids TDZ by initializing as undefined.
Q: What is hoisting?
JS moves declarations to the top of their scope before execution. var → hoisted as undefined. let/const → hoisted but stay in TDZ. Functions → fully hoisted.
Q: Why does "Loop done!" print before 0,1,2?
setTimeout is async — it goes to Web APIs, not Call Stack. console.log("Loop done!") is synchronous and runs on the Call Stack immediately. Callbacks wait until the stack is empty.
