Section 01
What is a Callback Function?
A function passed as an argument to another function, called when a task completes
Simple Definition

A callback is a function you give to another function and say "call this when you're done."

The function receiving the callback decides when to call it — immediately or later.

Real-Life Analogy

🍕 You order pizza and give your phone number (callback).

The pizza shop calls you back when it's ready — you don't wait by the phone!

You continue your work while pizza is being made (non-blocking).

callback-basic.js 
// Simplest callback example
function greet(name, callback) {
  let message = `Hello, ${name}!`;
  callback(message);           // call the passed function
}

// Pass a function as argument
greet("Ravi", (msg) => {
  console.log(msg);            // "Hello, Ravi!"
});

// Use different callbacks with SAME function
greet("Ravi", (msg) => console.log(msg.toUpperCase())); // "HELLO, RAVI!"
greet("Ravi", (msg) => alert(msg));   // shows alert
Why callbacks exist: JavaScript is single-threaded. Callbacks let you say "do this task, and when done — run this function." This keeps JS non-blocking and responsive.
Section 02
Types of Callbacks
Synchronous callbacks run immediately — Asynchronous callbacks run later
Synchronous Callback

Runs immediately inside the function call. No waiting.

sync-callback.js 
// map, filter, forEach = sync callbacks
[1,2,3].map(n => n * 2);  // runs immediately

function calculate(a, b, op) {
  return op(a, b);  // called right now
}
calculate(5, 3, (a,b) => a + b); // 8
Asynchronous Callback

Runs later — after a delay, event, or async operation.

async-callback.js 
// setTimeout = async callback
console.log("Start");

setTimeout(() => {
  console.log("Runs after 2 seconds");
}, 2000);

console.log("End");

// Output order:
// "Start"    ← immediate
// "End"      ← immediate
// "Runs after 2 seconds" ← later!
Error-First Callback (Node.js Pattern)

Standard Node.js convention: first parameter is error, second is data.

error-first.js 
// Pattern: callback(error, data)
function divideNumbers(a, b, callback) {
  if (b === 0) {
    callback(new Error("Cannot divide by zero"), null);
  } else {
    callback(null, a / b);  // null = no error
  }
}

divideNumbers(10, 2, (err, result) => {
  if (err) {
    console.log("Error:", err.message);
  } else {
    console.log("Result:", result);  // 5
  }
});

divideNumbers(10, 0, (err, result) => {
  if (err) console.log("Error:", err.message);
  // "Error: Cannot divide by zero"
});
Higher-Order Functions with Callbacks

Functions that take other functions as arguments. All built-in array methods use callbacks!

higher-order.js 
// Build your own map() — shows HOW callbacks work
function myMap(arr, callback) {
  let result = [];
  for (let i = 0; i < arr.length; i++) {
    result.push(callback(arr[i], i, arr)); // element, index, array
  }
  return result;
}

myMap([1,2,3], n => n * 2);   // [2, 4, 6]
myMap([1,2,3], n => n > 1);   // [false, true, true]

// Build your own filter()
function myFilter(arr, callback) {
  let result = [];
  for (let item of arr) {
    if (callback(item)) result.push(item);
  }
  return result;
}

myFilter([1,2,3,4,5], n => n % 2 === 0); // [2, 4]
Section 03
Callback Hell — The Problem
When callbacks nest inside callbacks inside callbacks — creating the "pyramid of doom"
❌ Callback Hell
getUser(id, (user) => {
  getOrders(user.id, (orders) => {
    getPayment(orders[0].id, (payment) => {
      getInvoice(payment.id, (invoice) => {
        sendEmail(invoice, (result) => {
          // Lost in nesting! 😱
          console.log(result);
        });
      });
    });
  });
});
✅ With Promises
getUser(id)
  .then(user => getOrders(user.id))
  .then(orders => getPayment(orders[0].id))
  .then(payment => getInvoice(payment.id))
  .then(invoice => sendEmail(invoice))
  .then(result => {
    // Clean and readable! ✅
    console.log(result);
  })
  .catch(err => console.log(err));
Problems with Callback Hell: Hard to read, hard to debug, hard to handle errors, hard to add logic between steps. This is exactly why Promises were invented!
Advanced Callbacks — debounce() & once()
advanced-callbacks.js 
// once() — function runs ONLY on first call
function once(fn) {
  let called = false, result;
  return function(...args) {
    if (!called) { called = true; result = fn(...args); }
    return result;
  };
}

const init = once(() => { console.log("Initialized!"); return 42; });
init();  // "Initialized!" → 42
init();  // silent → 42

// debounce() — waits until user STOPS calling
function debounce(fn, delay) {
  let timer;
  return function(...args) {
    clearTimeout(timer);
    timer = setTimeout(() => fn(...args), delay);
  };
}

const search = debounce((q) => console.log(`Search: ${q}`), 500);
search("R");     // reset timer
search("Ra");    // reset timer
search("Ravi");  // after 500ms → "Search: Ravi"

Q3
Write a retry(fn, times, callback) function that retries a failing function up to times times before giving up.
Hard
answer-q3.js
function retry(fn, times, callback) {
  try {
    let result = fn();
    callback(null, result);
  } catch (err) {
    if (times > 0) {
      console.log(`Retrying... (${times} left)`);
      retry(fn, times - 1, callback);
    } else {
      callback(err, null);
    }
  }
}

let attempt = 0;
function unstable() {
  attempt++;
  if (attempt < 3) throw new Error("Network error");
  return "Success!";
}

retry(unstable, 3, (err, result) => {
  if (err) console.log("Failed:", err.message);
  else console.log("✅", result);
});
// Retrying... (3 left)
// Retrying... (2 left)
// ✅ Success!

Q5 — Playwright
Write a runTestsSequentially(tests, finalCallback) that runs each test one by one using callbacks, collecting results, then calls finalCallback with summary.
Hard Playwright
answer-q5.js
function runTest(name, callback) {
  setTimeout(() => {
    let status = Math.random() > 0.3 ? "pass" : "fail";
    callback(null, { name, status });
  }, Math.random() * 500);
}

function runTestsSequentially(tests, finalCallback) {
  let results = [], index = 0;

  function runNext() {
    if (index >= tests.length) {
      let passed = results.filter(r => r.status === "pass").length;
      finalCallback(null, { total: results.length, passed, results });
      return;
    }
    runTest(tests[index++], (err, result) => {
      console.log(`${result.status === "pass" ? "✅" : "❌"} ${result.name}`);
      results.push(result);
      runNext();
    });
  }

  runNext();
}

runTestsSequentially(["Login","Signup","Checkout"], (err, summary) => {
  console.log(`\n📊 ${summary.passed}/${summary.total} passed`);
});
Section 05
What is a Promise?
An object representing the eventual completion or failure of an async operation
Simple Definition

A Promise is a placeholder for a value you don't have yet but will get in the future.

Like an IOU note — "I promise to give you the data when it's ready."

Zomato Analogy

🍕 You place an order → get an order ID (Promise)

You continue doing other things while it's being prepared

Later: Food arrives ✅ (resolved) or Order cancelled ❌ (rejected)

Creating & Consuming a Promise
promise-basic.js
// ─── CREATING ───────────────────────────────────────
let myPromise = new Promise((resolve, reject) => {
  let success = true;

  if (success) {
    resolve("Data received!");    // ✅ Fulfil it
  } else {
    reject(new Error("Failed!")); // ❌ Reject it
  }
});

// ─── CONSUMING ──────────────────────────────────────
myPromise
  .then(data  => console.log("✅ Success:", data))
  .catch(err  => console.log("❌ Error:", err.message))
  .finally(()  => console.log("Always runs!"));

// Output: ✅ Success: Data received!
//         Always runs!
Section 06
Promise States & Chaining
A Promise is always in one of three states — and .then() chains are how you sequence async work
⏳ PENDING

Initial state. Neither fulfilled nor rejected. Operation is still running.

let p = new Promise((res) => {
  // Still running...
});
// p is PENDING
✅ FULFILLED

Operation succeeded. resolve() was called. .then() handler runs.

let p = new Promise((res) => {
  res("Success!");
});
// p is FULFILLED
❌ REJECTED

Operation failed. reject() was called. .catch() handler runs.

let p = new Promise((_, rej) => {
  rej(new Error("Failed"));
});
// p is REJECTED
Promise Chaining — Sequential Async Operations
chaining.js
function step1() {
  return new Promise(res => setTimeout(() => res("Step 1 done"), 1000));
}
function step2(data) {
  return new Promise(res => setTimeout(() => res(data + " → Step 2 done"), 1000));
}
function step3(data) {
  return new Promise(res => setTimeout(() => res(data + " → Step 3 done"), 1000));
}

// Each .then() receives result of previous
step1()
  .then(data => step2(data))
  .then(data => step3(data))
  .then(result => console.log(result))
  .catch(err => console.log("Error:", err));

// After 3 seconds: "Step 1 done → Step 2 done → Step 3 done"
Section 07
All Promise Methods
Six static methods — each with a distinct purpose
MethodWaits ForFails IfUse Case
Promise.all() ALL resolve ANY rejects Load all data before rendering
Promise.allSettled() ALL settle Never rejects Run all tests, collect results
Promise.race() FIRST settles If FIRST rejects Timeout pattern
Promise.any() FIRST resolves ALL reject Try fastest server
Promise.resolve(val) — Never Wrap value in Promise
Promise.reject(err) — Always Immediately reject
Promise.all() — All Must Pass
// All run SIMULTANEOUSLY — faster!
Promise.all([
  fetch('/api/users'),
  fetch('/api/orders'),
  fetch('/api/products')
]).then(([users, orders, products]) => {
  // All three loaded!
}).catch(err => {
  // ONE failed → all fail
});
Promise.allSettled() — No Failure
Promise.allSettled([
  Promise.resolve("pass"),
  Promise.reject(new Error("fail")),
  Promise.resolve("pass")
]).then(results => {
  results.forEach(r => {
    if (r.status === "fulfilled")
      console.log("✅", r.value);
    else
      console.log("❌", r.reason.message);
  });
});
Promise.race() — Timeout Pattern
function fetchWithTimeout(url, ms) {
  let fetchP = fetch(url).then(r => r.json());
  let timeoutP = new Promise((_, rej) =>
    setTimeout(() =>
      rej(new Error("Timeout!")), ms)
  );
  return Promise.race([fetchP, timeoutP]);
}
Promise.any() — First Success
// Try multiple servers, use fastest
Promise.any([
  fetch('https://server1.com/api'),
  fetch('https://server2.com/api'),
  fetch('https://server3.com/api')
]).then(res => console.log("Fastest:", res))
  .catch(() => console.log("All failed!"));
Section 08
async / await
Syntactic sugar on top of Promises — makes async code look synchronous
async/await Rules
  • async before function — makes it return a Promise automatically
  • await pauses execution until Promise resolves
  • await can only be used inside async functions
  • Use try/catch for error handling (replaces .catch())
Promise Chain Way
getUser(id)
  .then(user => getOrders(user.id))
  .then(orders => getPayment(orders[0].id))
  .then(payment => {
    console.log(payment);
  })
  .catch(err => console.log(err));
async/await Way (Same thing!)
async function process(id) {
  try {
    const user = await getUser(id);
    const orders = await getOrders(user.id);
    const payment = await getPayment(orders[0].id);
    console.log(payment);
  } catch(err) { console.log(err); }
}
async/await with Promise.all (Parallel!)
parallel-async.js
async function loadDashboard() {

    // ❌ Sequential — slow! (each waits for previous)

      getUser(),

// ✅ With proper error handling:
async function fetchUser(id) {
  let isLoading = true;
  try {
    const res = await fetch(`/api/users/${id}`);
    if (!res.ok) throw new Error(`HTTP error: ${res.status}`);

    return null;
  } finally {
    isLoading = false;
    console.log("Loading complete"); // always runs
  }
}

// Simulate async operations
const login = (u, p) => new Promise((res, rej) =>
  setTimeout(() =>
    u === "admin" ? res("token_abc123") : rej(new Error("Invalid creds")), 400));

const runTest = (name) => new Promise(res =>
  setTimeout(() => res({name, status:Math.random()>.3?"pass":"fail"}),

async function runPlaywrightSuite() {
  console.log("🚀 Starting Playwright Suite\n");

  try {
    // Step 1: Login
    const token = await login("admin", "pass");
    console.log("1️⃣  Login ✅ Token:", token);

    // Step 2: Run ALL tests in parallel
    const testNames = ["Login", "Signup", "Checkout", "Profile", "Dashboard"];

    });

  } catch (err) {
    console.log("❌ Suite failed:", err.message);
  } finally {
    console.log("✔️  Suite complete");
  }
}

Section 10
Interview Questions & Answers
Top questions asked at FAANG and product companies — with clear answers
🔶 Callback Interview Questions
Q: What is a callback function?
A function passed as an argument to another function and called when that function completes its task. It enables async operations by saying "when done, run this."
Q: Sync vs async callbacks?
Sync callbacks run immediately (map, filter, forEach). Async callbacks run later after a delay or event (setTimeout, fetch, event listeners). Async callbacks don't block execution.
Q: What is callback hell?
When callbacks nest deeply inside each other creating a "pyramid of doom." Hard to read, debug, and maintain. Solved by Promises and async/await.
Q: What is the error-first pattern?
Node.js convention where callback's first parameter is the error, second is data: callback(err, data). Always check if err is truthy before using data.
Q: What is a higher-order function?
A function that accepts another function as an argument or returns a function. map(), filter(), reduce() are HOFs. They enable callbacks and functional programming.
Q: What is debounce?
A technique using callbacks and closures that delays function execution until after a set time has passed since the last call. Used in search boxes to avoid firing on every keystroke.
🔵 Promise Interview Questions
Q: What is a Promise?
An object representing eventual completion or failure of an async operation. Has 3 states: pending, fulfilled, rejected. Consumed via .then(), .catch(), .finally().
Q: Difference between Promise.all() and Promise.allSettled()?
Promise.all() fails fast — if ANY promise rejects, it rejects immediately. Promise.allSettled() waits for ALL to complete regardless, returning status of each. Use allSettled when you want all results even with failures.
Q: What is Promise chaining?
Each .then() returns a new Promise, enabling sequential async operations. The return value of .then() is passed to the next .then(). Errors propagate to the first .catch().
Q: Callback vs Promise?
Callbacks can cause nesting hell and make error handling complex. Promises provide .then() chaining, single .catch() for errors, and access to static methods like Promise.all(). Promises are built on callbacks internally.
Q: What does async/await do?
Syntactic sugar over Promises. async makes a function return a Promise. await pauses execution inside the async function until the Promise resolves. Makes async code look and behave like synchronous code.
Q: Promise.race() vs Promise.any()?
race() resolves or rejects with the FIRST settled promise — whether success or failure. any() only resolves with the FIRST successful promise, ignoring rejections unless ALL reject (AggregateError).

Quick Reference — Cheat Sheet
cheatsheet.js
// ── CALLBACK ──────────────────────────────────────────────
function doWork(callback) { callback(null, result); }
doWork((err, data) => { if (err) return; /* use data */ });

// ── PROMISE ───────────────────────────────────────────────
new Promise((resolve, reject) => resolve(data))
  .then(data => data)
  .catch(err => err)
  .finally(() => console.log("done"));

// Static methods
Promise.all([p1, p2]);          // all must pass
Promise.allSettled([p1, p2]);   // wait for all
Promise.race([p1, p2]);         // first wins
Promise.any([p1, p2]);          // first success
Promise.resolve(val);           // already resolved
Promise.reject(err);            // already rejected

// ── ASYNC/AWAIT ───────────────────────────────────────────
async function fn() {
  try {
    const data = await somePromise;
    const [a, b] = await Promise.all([p1, p2]);
  } catch(err) { console.log(err); }
  finally { console.log("always"); }
}
