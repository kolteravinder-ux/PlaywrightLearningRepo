1. OOPs Concepts

1.1 The Four Pillars

PillarWhat it meansJava example
EncapsulationBinding data and methods together, hiding internal stateprivate fields + public getters/setters
InheritanceOne class acquires properties of anotherclass Car extends Vehicle
PolymorphismOne interface, many implementationsMethod overloading & overriding
AbstractionHiding implementation, exposing only behaviorabstract class / interface
Q: Can you explain the four OOPs pillars in your own words?
Interview Answer I'd explain it with a real-world analogy. Encapsulation is like a capsule medicine — the ingredients are hidden inside, you only interact with the outer shell (the public methods). In Java I achieve this by keeping fields private and exposing controlled access through getters/setters.

Inheritance is reusing behavior — a Car "is-a" Vehicle, so it inherits common fields like speed and fuel from the Vehicle class instead of rewriting them.

Polymorphism means the same method name behaves differently depending on context — compile-time (overloading, same method name different parameters) and runtime (overriding, subclass changes parent's behavior). In my Selenium framework I use runtime polymorphism heavily — e.g., a common BasePage reference pointing to different page objects.

Abstraction is about hiding "how" and exposing only "what" — like a WebDriver interface where I don't care how ChromeDriver implements findElement(), I just call it.

1.3 Inheritance — Types

  • Single — B extends A
  • Multilevel — C extends B extends A
  • Hierarchical — B and C both extend A
  • Multiple (not via classes) — Java doesn't support multiple inheritance with classes (diamond problem), but achieves it via interfaces
Q: Why doesn't Java support multiple inheritance with classes?
Interview Answer To avoid the diamond problem — if two parent classes have a method with the same signature, the compiler wouldn't know which one the child should inherit. Java sidesteps this by allowing a class to implement multiple interfaces instead. Since Java 8, interfaces can have default methods, so ambiguity can still occur there — in that case, Java forces the implementing class to explicitly override the method to resolve the conflict.

Q: When would you use an abstract class over an interface?
Interview Answer I go with an abstract class when I want to share common code across related classes — for example, in my Selenium framework, a BasePage abstract class holds common methods like waitForElement() or clickElement() that every page object reuses. I go with an interface when I only want to define a contract — like an APIClient interface with get(), post() methods, without caring how each implementation works internally.

1.11 Composition vs Inheritance

Q: What's the difference between "is-a" and "has-a" relationships?
Interview Answer Inheritance models an "is-a" relationship — a Car is a Vehicle. Composition models a "has-a" relationship — a Car has an Engine. I generally prefer composition over inheritance where possible because it's more flexible — you can swap the Engine implementation at runtime without rewriting the class hierarchy, whereas inheritance is a rigid compile-time relationship. In my framework, my TestBase class "has-a" WebDriver instance rather than extending some driver class.

  • static methods — utility methods callable via interface name
  • Functional Interface — exactly one abstract method (e.g. Runnable, Comparator), enables lambda expressions, marked with @FunctionalInterface

2.1 Hierarchy Overview

Collection interface → List, Set, Queue  |  Map is separate (not a Collection)

  • List — ordered, allows duplicates → ArrayList, LinkedList, Vector
  • Set — no duplicates → HashSet, LinkedHashSet, TreeSet

2.2 ArrayList vs LinkedList

Q: Which do you use in your automation framework and why?
Interview Answer I mostly use ArrayList — for example, storing a list of WebElements from findElements(), or reading test data rows. Since I mostly iterate and read, not frequently insert into the middle, ArrayList's O(1) random access fits better. I'd reach for LinkedList only if I were building something like a queue of test steps where I insert/remove from both ends frequently.

2.4 HashMap Internal Working

Q: How does HashMap work internally?
Interview Answer Internally a HashMap is an array of "buckets". When I put a key-value pair, Java calls hashCode() on the key, then applies its own hash-spreading function to reduce collisions, and uses index = hash & (capacity-1) to decide the bucket. If two keys land in the same bucket (a collision), they're stored as a linked list — and since Java 8, if a bucket has 8+ nodes, it converts to a Red-Black tree for faster lookup — O(log n) instead of O(n). When I call get(), it hashes the key again, jumps to the bucket, then uses equals() to find the exact match. Default capacity is 16, and it resizes (doubles) once it crosses the load factor, typically 0.75.

2.5 HashSet vs TreeSet vs LinkedHashSet

  • HashSet — backed by HashMap internally, no order, O(1)
  • LinkedHashSet — maintains insertion order
  • TreeSet — sorted order, backed by TreeMap, O(log n)

Q: When would you choose Comparator over Comparable?
Interview Answer Comparable is used when a class has one obvious natural ordering — like sorting Employees by ID always. But if I need to sort the same object differently in different contexts — say sort by age in one test and by salary in another — I use Comparator, because I can define as many comparator implementations as I need without touching the original class.

2.9 Generics

class Box<T> {
    private T value;
    void set(T value){ this.value = value; }
    T get(){ return value; }
}

Q: Why use Generics?
Interview Answer Generics give compile-time type safety and remove the need for explicit casting. Before generics, a List stored Objects, so you'd get a ClassCastException at runtime if wrong data was retrieved. With List<String>, the compiler itself blocks adding an Integer, catching bugs early instead of at runtime — which matters a lot in test automation since I want failures caught during compilation, not mid-test-run.

3.1 Exception Hierarchy

Throwable

  • Error — serious JVM-level problems (OutOfMemoryError, StackOverflowError) — not meant to be caught
  • Exception
    • Checked — checked at compile time (IOException, SQLException)
    • Unchecked / RuntimeException — checked at runtime (NullPointerException, ArrayIndexOutOfBoundsException, ArithmeticException)

3.2 Checked vs Unchecked

CheckedUnchecked
Must be handled (try-catch or throws) at compile timeNot enforced by compiler
Represents recoverable conditionsUsually programming errors

Q: Give an example of checked vs unchecked exception from your Selenium framework.
Interview Answer A checked exception I regularly handle is IOException — for example when reading a properties file or Excel sheet using Apache POI, the compiler forces me to either catch it or declare throws IOException. An unchecked one would be NoSuchElementException from Selenium itself, or a NullPointerException if a WebElement wasn't initialized — these aren't forced by the compiler, so I add explicit checks and waits to prevent them proactively.

3.3 try-catch-finally

  • finally executes whether or not an exception occurs — used for resource cleanup (closing driver, DB connection)
  • Multiple catch blocks allowed, ordered from most specific to most general
  • Java 7+ supports multi-catch: catch (IOException | SQLException e)
  • try-with-resources auto-closes resources implementing AutoCloseable

Interview Answer I created custom exceptions like FrameworkException or ElementNotInteractableCustomException to give more meaningful, framework-specific error messages instead of generic ones. Q: How do you handle StaleElementReferenceException in your framework?
Interview Answer It usually happens after a page refresh, AJAX update, or navigation, when the previously located WebElement no longer maps to a node in the current DOM. I handle it by re-locating the element rather than reusing the stale reference — I've wrapped this in a retry utility method that catches StaleElementReferenceException, re-finds the element by its locator, and retries the action once or twice before failing the test, instead of letting the whole test crash on a transient DOM change.

4. Selenium WebDriver

4.1 Architecture

Selenium client library (Java bindings) → JSON Wire Protocol / W3C WebDriver Protocol → Browser Driver (chromedriver/geckodriver) → Browser

Q: Explain the Selenium WebDriver architecture.
Interview Answer When I write driver.get("url") in Java, the language binding converts that into an HTTP request following the W3C WebDriver protocol — basically a JSON payload. This is sent to the browser-specific driver, like chromedriver, which runs as a separate server process. Chromedriver then translates that request into native browser calls via the browser's own automation API and returns the result back as an HTTP response. Since Selenium 4, everything strictly follows the W3C standard, whereas earlier versions used the older JSON Wire Protocol.

4.3 XPath Types & Axes

  • Absolute XPath: /html/body/div/form/input — fragile, breaks with DOM changes
  • Relative XPath: //input[@id='email'] — preferred, resilient
  • Functions: contains(), starts-with(), text(), normalize-space()
  • Axes: parent::, following-sibling::, preceding-sibling::, ancestor::, descendant::
//input[contains(@id,'user')]
//div[@class='card']//following-sibling::button
//label[text()='Email']/following-sibling::input
Q: CSS Selector or XPath — which do you prefer and why?
Interview Answer I prefer CSS selectors when possible because they're generally faster since the browser engine natively parses CSS, whereas XPath needs an additional engine, especially on older IE-type browsers. But I switch to XPath when I need to traverse upward in the DOM — like locating a parent from a child, or matching partial text — since CSS can't traverse to a parent or match on visible text. So my rule of thumb: CSS for straightforward, front-facing attributes; XPath for text-based or parent-relative logic.

4.4 Waits

Wait TypeBehavior
Implicit WaitGlobal wait applied to all findElement calls; polls DOM up to timeout
Explicit Wait (WebDriverWait)Waits for a specific condition on a specific element
Fluent WaitExplicit wait + configurable polling frequency + ignore specific exceptions
WebDriverWait wait = new WebDriverWait(driver, Duration.ofSeconds(10));
wait.until(ExpectedConditions.elementToBeClickable(By.id("submit"))).click();

FluentWait<WebDriver> fwait = new FluentWait<>(driver)
    .withTimeout(Duration.ofSeconds(20))
    .pollingEvery(Duration.ofSeconds(2))
    .ignoring(NoSuchElementException.class);
Q: Why shouldn't you mix implicit and explicit waits?
Interview Answer Mixing them can cause unpredictable wait times because both waits poll the DOM independently, and their timers can stack — for example if implicit wait is 10 seconds and an explicit wait condition also needs to poll, in some driver versions the effective wait becomes the sum of both, causing tests to hang far longer than expected. In my framework I standardized on explicit waits only, keeping implicit wait at 0, so the wait behavior stays predictable and I control each wait condition precisely per element.

4.7 Page Object Model (POM) & Page Factory

Q: What is the Page Object Model and why do you use it?
Interview Answer POM is a design pattern where each web page is represented as a class — the page's locators are stored as fields and its user actions as methods. The main benefit is separation of concerns: my test scripts describe "what to do" (business flow), while the page classes handle "how to do it" (locators, low-level Selenium calls). So if a locator changes because of a UI update, I fix it in exactly one place — the page class — instead of every test that touches that element. I typically pair it with PageFactory and @FindBy annotations for cleaner element initialization, and lately I've also used it alongside a fluent-style method chaining approach. 
public class LoginPage {
    WebDriver driver;
    @FindBy(id = "username") WebElement username;
    @FindBy(id = "password") WebElement password;
    @FindBy(id = "loginBtn") WebElement loginBtn;

    public LoginPage(WebDriver driver){
        this.driver = driver;
        PageFactory.initElements(driver, this);
    }
    public void login(String user, String pass){
        username.sendKeys(user);
        password.sendKeys(pass);
        loginBtn.click();
    }
}

4.8 Selenium Grid

Q: What is Selenium Grid and how have you used it?
Interview Answer Selenium Grid lets me run tests on multiple machines/browsers in parallel using a Hub-Node architecture — the Hub receives test requests and routes them to available Nodes matching the desired browser/OS capability. In my project we used a Grid setup (self-hosted, and separately BrowserStack as a cloud grid) to cut regression suite execution time significantly by distributing tests across parallel nodes, combined with TestNG's parallel execution attribute.

  • Relative Locators — above(), below(), toLeftOf(), toRightOf(), near()
  • New Chrome DevTools Protocol (CDP) integration — network interception, console logs, geolocation
  • Native support for multi-tab/window handling improvements

4.10 Synchronization Issues & Flaky Tests

Q: How do you deal with flaky tests in your suite?
Interview Answer Most flakiness in my experience traces back to synchronization — the test running faster than the application's UI response. I address this with explicit waits tied to specific conditions rather than hard Thread.sleep(). Where flakiness is due to environment issues, I've added a controlled retry mechanism using TestNG's IRetryAnalyzer, but only as a safety net — not a substitute for fixing the root cause. I also track flaky tests separately in reporting so they don't silently mask real failures.

5. Maven Framework

5.1 What is Maven & Why

Q: Why do you use Maven in your automation framework?
Interview Answer Maven is a build automation and dependency management tool. Instead of manually downloading Selenium, TestNG, or Apache POI jars and configuring classpaths, I just declare them as dependencies in pom.xml, and Maven downloads them from the central repository along with their transitive dependencies. It also standardizes the project structure, manages the build lifecycle, and lets me trigger test execution, generate reports, and integrate with Jenkins — all through simple mvn commands, which is essential for CI/CD pipelines.

6. TestNG

6.1 Why TestNG over JUnit

Q: Why did you choose TestNG over JUnit?
Interview Answer TestNG gives more powerful features out of the box that suit UI automation better — like native support for test prioritization, grouping tests (smoke/regression), parallel execution at method/class/suite level, data-driven testing via @DataProvider, and flexible dependency management with dependsOnMethods. JUnit 5 has since caught up with some of these, but at the time our framework was built, TestNG's XML-based suite configuration and reporting fit our CI pipeline better, so we standardized on it.

6.2 Annotations & Execution Order

AnnotationRuns
@BeforeSuite / @AfterSuiteOnce before/after entire suite
@BeforeTest / @AfterTestOnce before/after a <test> tag in XML
@BeforeClass / @AfterClassOnce before/after all methods in a class
@BeforeMethod / @AfterMethodBefore/after each @Test method
@TestThe actual test method
Order: BeforeSuite → BeforeTest → BeforeClass → BeforeMethod → Test → AfterMethod → AfterClass → AfterTest → AfterSuite

6.3 TestNG Assertions

Assert.assertEquals(actual, expected, "mismatch message");
Assert.assertTrue(isDisplayed);
Assert.assertNotNull(element);

// Soft Assert - collects failures, doesn't stop execution
SoftAssert softAssert = new SoftAssert();
softAssert.assertEquals(actualTitle, expectedTitle);
softAssert.assertTrue(isLoggedIn);
softAssert.assertAll(); // must call at end to report failures
Q: Difference between hard assert and soft assert?
Interview Answer A hard assert (Assert.assertEquals) stops test execution immediately on failure, throwing an AssertionError. A soft assert collects all failures but keeps executing the rest of the test, and only reports them when I explicitly call assertAll(). I use soft asserts when validating multiple independent fields on a page — like verifying five different labels — so I get one full failure report instead of the test stopping at the first mismatch, which saves debugging time.

Q: How do you achieve parallel execution in TestNG?
Interview Answer I set the parallel attribute on the <suite> tag in testng.xml — options are methods, classes, tests, or instances — along with a thread-count. In my framework I use parallel="classes" since each class maps to one browser session, and I pair it with a ThreadLocal<WebDriver> in my base class so each thread gets its own independent driver instance — that's crucial, because sharing a single static driver across threads causes tests to interfere with each other.

@Test(dependsOnMethods = {"loginTest"})

  • priority — lower value runs first (default 0)
  • dependsOnMethods — skips dependent test if the parent fails
  • groups — logical tagging (smoke, regression, sanity) to selectively run subsets

6.7 Listeners

Q: What are TestNG Listeners and how have you used them?
Interview Answer Listeners let me hook into the test lifecycle without touching individual test methods. I've implemented ITestListener to automatically capture a screenshot and attach it to the report whenever onTestFailure() fires — that way I don't need to add screenshot code inside every single test. I've also used IRetryAnalyzer combined with a listener to automatically retry a failed test a set number of times before marking it a genuine failure, which helps filter out transient environment flakiness from real bugs. 
public class TestListener implements ITestListener {
    @Override
    public void onTestFailure(ITestResult result){
        // capture screenshot logic here
    }
}

Q: Walk me through how you'd validate a POST API response.
Interview Answer I use REST Assured's given-when-then BDD style. In given(), I set up the base URI, headers, and request body/payload — usually built from a POJO serialized to JSON. In when(), I specify the HTTP method and endpoint. In then(), I validate the response — status code, response time, and specific fields in the JSON body using JsonPath expressions like body("data.id", notNullValue()). For complex responses I deserialize into a POJO using Jackson/Gson and assert on the object directly rather than raw JsonPath strings, which is cleaner for larger payloads.

7.6 API vs UI Testing

Q: Why is API testing preferred earlier in the pipeline compared to UI testing?
Interview Answer API tests are faster and far more stable since they skip rendering, JavaScript execution, and browser quirks — they hit the business logic layer directly. This means I can validate backend behavior, edge cases and error handling much earlier and faster than UI tests, which is exactly the shift-left principle in the testing pyramid: many fast API/unit tests at the base, fewer slower UI tests at the top. In my projects, I use API calls not just for testing endpoints directly but also to set up test data or verify backend state after a UI action, instead of relying purely on UI-based verification.

8.4 WHERE vs HAVING

Q: Difference between WHERE and HAVING?
Interview Answer WHERE filters individual rows before any grouping happens, and can't be used with aggregate functions like COUNT() or SUM(). HAVING filters after GROUP BY has aggregated the rows, so it's used specifically to filter on aggregate results — for example, finding departments having more than 5 employees. 
SELECT dept_id, COUNT(*) as cnt
FROM Employee
WHERE status = 'ACTIVE'
GROUP BY dept_id
HAVING COUNT(*) > 5;

9.1 Reverse a String

public static String reverse(String str){
    return new StringBuilder(str).reverse().toString();
}
// Manual approach (without built-in)
public static String reverseManual(String str){
    char[] chars = str.toCharArray();
    int left = 0, right = chars.length - 1;
    while (left < right) {
        char temp = chars[left];
        chars[left++] = chars[right];
        chars[right--] = temp;
    }
    return new String(chars);
}
Interview Answer The simplest way is StringBuilder.reverse(), but interviewers often want the manual logic to test understanding — I use a two-pointer approach, swapping characters from both ends toward the middle, giving O(n) time and O(1) extra space (excluding the output array).

9.2 Check Palindrome

public static boolean isPalindrome(String str){
    int left = 0, right = str.length() - 1;
    while (left < right) {
        if (str.charAt(left++) != str.charAt(right--)) return false;
    }
    return true;
}

9.3 Find Duplicate Characters in a String

public static void findDuplicates(String str){
    Map<Character, Integer> map = new HashMap<>();
    for (char c : str.toCharArray()) {
        map.put(c, map.getOrDefault(c, 0) + 1);
    }
    for (Map.Entry<Character, Integer> entry : map.entrySet()) {
        if (entry.getValue() > 1)
            System.out.println(entry.getKey() + " -> " + entry.getValue());
    }
}
Interview Answer I use a HashMap to count character frequency in a single O(n) pass — key is the character, value is the count. At the end I iterate the map and print entries with count > 1. This is more efficient than a nested loop approach which would be O(n²).

9.5 Find Second Largest Number in Array

public static int secondLargest(int[] arr){
    int first = Integer.MIN_VALUE, second = Integer.MIN_VALUE;
    for (int n : arr) {
        if (n > first) { second = first; first = n; }
        else if (n > second && n != first) { second = n; }
    }
    return second;
}
Interview Answer I do it in a single pass, tracking two variables — first and second — instead of sorting the array, which would cost O(n log n). This way it's O(n) time and O(1) space. Whenever I find a number bigger than first, the old first becomes the new second.

9.6 Check if a Number is Prime

public static boolean isPrime(int n){
    if (n <= 1) return false;
    for (int i = 2; i <= Math.sqrt(n); i++) {
        if (n % i == 0) return false;
    }
    return true;
}

9.7 Fibonacci Series

// Iterative
public static void fibonacci(int n){
    int a = 0, b = 1;
    for (int i = 0; i < n; i++) {
        System.out.print(a + " ");
        int next = a + b; a = b; b = next;
    }
}
// Recursive
public static int fib(int n){
    if (n <= 1) return n;
    return fib(n-1) + fib(n-2);
}
Interview Answer I usually show the iterative version first since it's O(n) time and O(1) space, and mention that a naive recursive version is O(2ⁿ) due to repeated subproblem calculations — I'd only use recursion with memoization if the interviewer specifically asks for the recursive approach.

9.10 Sort an Array without built-in sort (Bubble Sort)

public static void bubbleSort(int[] arr){
    for (int i = 0; i < arr.length - 1; i++) {
        for (int j = 0; j < arr.length - 1 - i; j++) {
            if (arr[j] > arr[j+1]) {
                int temp = arr[j]; arr[j] = arr[j+1]; arr[j+1] = temp;
            }
        }
    }
}

9.11 Find Missing Number in Array (1 to N)

public static int findMissing(int[] arr, int n){
    int expectedSum = n * (n+1) / 2;
    int actualSum = 0;
    for (int num : arr) actualSum += num;
    return expectedSum - actualSum;
}

9.12 Singleton Design Pattern (WebDriver instance)

public class DriverManager {
    private static WebDriver driver;
    private DriverManager(){}
    public static WebDriver getDriver(){
        if (driver == null) {
            driver = new ChromeDriver();
        }
        return driver;
    }
}
Interview Answer Singleton ensures only one instance of a class exists across the JVM. I use it for WebDriver management — the private constructor blocks external instantiation, and getDriver() lazily creates the driver only once. In a multi-threaded parallel run, I upgrade this to a ThreadLocal<WebDriver> instead, so each thread still gets exactly one driver instance, but scoped per-thread rather than truly global — otherwise parallel tests would collide on a shared browser session.

9.13 Multi-threading Basics (relevant to parallel execution)

public class DriverManager {
    private static ThreadLocal<WebDriver> driver = new ThreadLocal<>();
    public static void setDriver(WebDriver d){ driver.set(d); }
    public static WebDriver getDriver(){ return driver.get(); }
    public static void unload(){ driver.remove(); }
}
Interview Answer ThreadLocal gives each thread its own isolated copy of a variable — so when TestNG runs classes in parallel, each thread calls setDriver() in its own @BeforeMethod, and since the variable is thread-scoped, thread A can never accidentally read thread B's driver instance. I always call unload() or driver.remove() in @AfterMethod to avoid memory leaks, since ThreadLocal values persist until explicitly cleared or the thread dies.
