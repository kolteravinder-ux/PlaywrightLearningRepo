Topic 01
⬆️ What is Hoisting?
JavaScript moves declarations to the top before execution

DEFINITION

Hoisting is JavaScript's behavior of moving all declarations (var, let, const, function) to the top of their scope before code executes — but NOT the assignments/initializations.

Think of it like this: JavaScript reads your code in 2 passes:
Pass 1 — Collect all declarations and move them to the top
Pass 2 — Execute code line by line

QUICK EXAMPLE

// What you write:
console.log(name); // undefined
var name = "Ravi";
console.log(name); // "Ravi"

// What JavaScript does (behind the scenes):
var name;              ← HOISTED to top
console.log(name); // undefined
name = "Ravi";         ← assignment stays here
console.log(name); // "Ravi"

KEY POINTS

  • Only declarations are hoisted — not initializations
  • var → hoisted and initialized as undefined
  • let/const → hoisted but NOT initialized (Temporal Dead Zone)
  • function declarations → fully hoisted (ready to use)
  • function expressions → treated like variables
Topic 02
📦 var Hoisting
var is hoisted and initialized as undefined

HOW var HOISTING WORKS

// Code you write:
console.log(x); // undefined (no error!)
var x = 5;
console.log(x); // 5

// What JavaScript executes:
var x;              ← declaration hoisted
console.log(x); // undefined (initialized but no value yet)
x = 5;              ← assignment happens here
console.log(x); // 5

var IN FUNCTIONS

function test() {
  console.log(a); // undefined
  var a = 10;
  console.log(a); // 10
}

// Behind the scenes:
function test() {
  var a;            ← hoisted to top of function
  console.log(a); // undefined
  a = 10;
  console.log(a); // 10
}
Key insight: var is hoisted to the top and immediately initialized as undefined. That's why you don't get an error — you just get undefined.
Topic 03
🔒 let/const Hoisting
let/const are hoisted but stay in Temporal Dead Zone

HOW let/const HOISTING WORKS

// Code you write:
console.log(x); // 🚨 ReferenceError!
let x = 5;
console.log(x); // 5

// What JavaScript does:
// TDZ STARTS ← x is hoisted but NOT initialized
console.log(x); // 🚨 ReferenceError — x is in TDZ!
let x = 5;        ← TDZ ENDS here
console.log(x); // 5 ✅

COMPARISON — var vs let

Aspectvarlet/const
Hoisted?✅ Yes✅ Yes
Initialized?✅ as undefined❌ No (TDZ)
Can use before declaration?✅ Yes (undefined)❌ No (Error)
Error typeNone (returns undefined)ReferenceError
Critical difference: Both var and let are hoisted. But var gives you undefined, while let throws an error because it's locked in the Temporal Dead Zone.
Topic 04
🚫 Temporal Dead Zone (TDZ)
The forbidden zone where let/const exist but cannot be accessed

WHAT IS TDZ?

Temporal Dead Zone (TDZ) is the time period between when a variable is hoisted and when it's actually initialized in your code.

During this zone:

  • The variable exists in memory (hoisted)
  • But you CANNOT access it — throws ReferenceError
  • It's "dead" — locked, untouchable, forbidden 🔒
Only affects: let and const (NOT var)

TDZ TIMELINE

Scope Starts
Variable is hoisted — TDZ BEGINS 🚫
Variable exists but is locked
During TDZ
Any access throws ReferenceError ❌
"Cannot access before initialization"
Declaration Line
TDZ ENDS ✅
Variable is initialized and ready to use
After Declaration
Variable can be accessed normally ✅

CODE EXAMPLE

// TDZ visualization
{
  // ← TDZ STARTS here for variable 'name'
  // name exists but is LOCKED 🔒
  
  console.log(name); // 🚨 ReferenceError — in TDZ!
  
  // Still in TDZ...
  
  let name = "Ravi"; ← TDZ ENDS here ✅
  
  console.log(name); // "Ravi" — now accessible ✅
}

COMMON TDZ MISTAKES

// Mistake 1: Using in own initialization
let x = x + 1; // 🚨 ReferenceError — x in TDZ on right side

// Mistake 2: typeof doesn't save you
typeof y; // 🚨 ReferenceError — y in TDZ
let y = 10;

// Mistake 3: Function parameter TDZ
function test(a = b, b = 2) {
  // 🚨 Error — b is in TDZ when evaluating default for 'a'
}
Topic 05
⚡ Function Hoisting
Function declarations are fully hoisted and ready to use

FUNCTION DECLARATION — FULLY HOISTED

// You can call before declaration!
greet(); // "Hello!" ✅ Works perfectly

function greet() {
  console.log("Hello!");
}

// Behind the scenes — function moved to top:
function greet() {      ← FULLY hoisted
  console.log("Hello!");
}
greet(); // "Hello!" ✅

FUNCTION EXPRESSION — NOT FULLY HOISTED

// Function expression with var
greet(); // 🚨 TypeError: greet is not a function

var greet = function() {
  console.log("Hello!");
};

// Behind the scenes:
var greet;            ← declaration hoisted as undefined
greet();            // 🚨 undefined is not a function!
greet = function() {  ← assignment happens here
  console.log("Hello!");
};

FUNCTION EXPRESSION WITH let — TDZ ERROR

// Function expression with let
greet(); // 🚨 ReferenceError — greet is in TDZ!

const greet = function() {
  console.log("Hello!");
};

COMPARISON TABLE

TypeCan call before?Hoisting behavior
Function declaration✅ YesFully hoisted — ready to use
Function expression (var)❌ Novar hoisted as undefined
Function expression (let/const)❌ NoTDZ — ReferenceError
Arrow function❌ NoSame as function expression

🌍 Real-Life Examples
Understand hoisting and TDZ through everyday analogies

🏨 EXAMPLE 1 — HOTEL ROOM BOOKING (TDZ)

THE SCENARIO
Day 1 (9 AM): You book Room 305 online
→ Room is RESERVED in system ✓ (hoisted)
→ But check-in is at 2 PM

Day 1 (12 PM): You arrive early and try to enter
Security: "🚨 Room 305 is reserved for you, but you're in the TEMPORAL DEAD ZONE. Check-in hasn't happened yet!"

Day 1 (2 PM): Check-in time ✓
→ You get the room key
→ NOW you can enter Room 305 ✅
JavaScript: Variable exists (hoisted) but locked in TDZ until initialization line 
// JavaScript equivalent:
{
  // TDZ starts ← room reserved but can't enter
  console.log(room); // 🚨 ReferenceError — TDZ!
  let room = 305; ← TDZ ends (check-in time)
  console.log(room); // 305 ✅
}

THE SCENARIO
Before restaurant opens:
Manager writes on board: "Paneer Tikka (coming soon)"

Restaurant opens:
Customer: "Do you have Paneer Tikka?"
Waiter: "Yes, it's on the board! But... it says 'coming soon'" (undefined)

Later:
Manager updates: "Paneer Tikka — ₹250" ✓
Now actually available!
var hoisting: Name exists (on board) but value comes later (undefined → actual price) 
// JavaScript equivalent:
console.log(dish); // undefined (on board but "coming soon")
var dish = "Paneer Tikka";
console.log(dish); // "Paneer Tikka" ✅

🏏 EXAMPLE 3 — CRICKET PLAYER IN QUARANTINE (TDZ)

THE SCENARIO
Day 1: Rohit Sharma selected for Indian team
→ Name added to roster ✓ (hoisted)
→ But mandatory 7-day quarantine 🏨

Day 3: Coach tries to call him for practice
Official: "🚨 Rohit is on the team but in QUARANTINE ZONE. You cannot contact him yet!"

Day 7: Quarantine ends ✓
→ Rohit joins team
→ NOW coach can call him ✅
TDZ: Player registered (hoisted) but in quarantine (locked) until cleared 
// JavaScript equivalent:
{
  // TDZ starts ← player in quarantine
  callPlayer(player); // 🚨 ReferenceError!
  let player = "Rohit"; ← quarantine ends
  callPlayer(player); // ✅ Works!
}

📦 EXAMPLE 4 — AMAZON PACKAGE (var vs let)

var — EMPTY BOX ARRIVES FIRST
Day 1: Empty package box arrives at door
You: "Is my laptop here?"
Box: "Yes I exist... but I'm empty" (undefined)

Day 3: Amazon fills the box
Box: "Now I have your MacBook Pro!" ✅
let — PACKAGE STUCK IN CUSTOMS
Day 1: Package exists in system but stuck in customs

Topic 07
🎯 Interview Q&A
Master these answers — commonly asked in interviews!
Q: What is hoisting?
JavaScript's behavior of moving declarations (var, let, const, function) to the top of their scope before code execution. Only declarations are hoisted, not initializations.
Q: Difference between var and let hoisting?
Both are hoisted. var is initialized as undefined (no error). let is hoisted but NOT initialized — stays in TDZ and throws ReferenceError if accessed before declaration.
Q: What is Temporal Dead Zone?
The time between when let/const is hoisted and when it's initialized. During TDZ, the variable exists but cannot be accessed — throws ReferenceError. Only affects let/const, not var.
Q: Can you use a function before declaration?
Yes for function declarations (fully hoisted). No for function expressions — they behave like variables. Arrow functions also cannot be used before declaration.
Q: Why does this code throw an error?
console.log(x); let x = 5;
x is in the Temporal Dead Zone. let is hoisted but NOT initialized. Accessing it before the declaration line throws ReferenceError.
Q: Why does this return undefined?
console.log(x); var x = 5;
var is hoisted and initialized as undefined. So console.log sees x exists but has no value yet. After assignment, x becomes 5.
Q: Are let and const hoisted?
Yes, but unlike var they are NOT initialized. They stay in the Temporal Dead Zone until their declaration line is reached. This prevents usage before declaration.
Q: What happens here?
greet(); var greet = function(){...}
TypeError: greet is not a function. The variable greet is hoisted as undefined. When you try to call undefined as a function, you get a TypeError.
Q: Why does function hoisting matter?
Function declarations are fully hoisted — you can organize code naturally (main logic first, helper functions below) without worrying about call order. Makes code more readable.
Q: Best practice to avoid hoisting bugs?
Always declare variables at the top of their scope. Use let/const (not var). Declare functions before calling them. The TDZ protection in let/const helps catch bugs early.
